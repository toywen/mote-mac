# 0024 同步第一版不做账户体系，只用设备令牌

- 状态：被 0025 替代
- 日期：2026-11-23

## 背景

[ADR 0022](0022-sync-service-deployment-and-latency.md) 决定同步服务只有一个用户，每台设备一个设备令牌。要做成什么样，有几种可能：

| 方案               | 适合谁                               | 代价                                     |
| ------------------ | ------------------------------------ | ---------------------------------------- |
| 设备令牌，没有账户 | 一个人、一个笔记库                   | 以后分享笔记库时要重做这一层             |
| 账户加设备         | 多人共用一个服务，或一个人多个笔记库 | 要做注册、登录、找回密码、邮箱验证       |
| 第三方登录         | 不想自己管密码                       | 依赖外部服务，iOS 端还要接入它的登录流程 |

## 决定

- 第一版没有账户。一个同步服务属于一个人。
- 设备由服务器上的命令行新建。命令打印设备令牌，只打印这一次。
- 服务端只存设备令牌的哈希、设备名和创建时间。撤销设备就是删掉这一行。
- 设备令牌是 32 字节的随机数。Mac 端存在系统钥匙串里，iOS 版发布后存在 Keychain 里。
- 协议里每个请求都带设备令牌。版本号按笔记库算，第一版一个服务器一个笔记库。
- 没有注册、登录、找回密码和邮箱验证。

以后要账户时这样做：

- 服务端加用户表，设备归属用户。
- 版本号改成按笔记库算，每个用户可以有多个笔记库。
- 协议加笔记库编号这个字段。
- 客户端加登录界面。

## 理由

- 只有你一个人用，账户体系全是空转。注册、登录和邮箱验证都要写、要测、要维护。
- 设备令牌已经够安全：长随机数、服务端只存哈希、随时能撤销。
- 加法式扩展留了路：用户表和笔记库编号都是往后加字段，不用改同步流程本身。

## 后果

- 以后想把笔记库分享给别人，账户这一层要重做，不是加个界面就行。
- 设备令牌泄露等于笔记库泄露。令牌只显示一次，用错设备时立刻撤销。
- 服务器上只有一个笔记库。要同步第二个笔记库，得再开一个同步服务实例。
