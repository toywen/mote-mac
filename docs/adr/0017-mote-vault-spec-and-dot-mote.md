# 0017. mote 独立笔记库规范与 .mote 目录

- 状态：已实现
- 日期：2026-11-21
- 替代：替代 0016 中依附 `.obsidian` 配置策略的决策

## 背景

此前 mote 将自己视为 Obsidian 的替代品，严格遵循 Obsidian 的目录与配置约定（如从 `.obsidian/app.json` 读取附件路径、默认将图片放入根目录、不写入任何库内私有目录等）。

但在实际使用中：
1. 默认存入根目录导致笔记库根目录严重杂乱。
2. 在可见目录中新建附件文件夹会污染左侧文件树与文件管理体验。
3. 强绑定 Obsidian 的历史配置限制了 mote 作为现代独立笔记软件的发展空间。

用户明确要求 mote 不用去兼容 Obsidian，建立 mote 独立的笔记库规范。

## 决定

1. **确立 `.mote/` 专属隐藏目录**：
   - 每个笔记库使用独立的 `.mote/` 目录组织元数据与资源。
   - `.mote/attachments/`：集中存放所有新粘贴、拖拽或插入的图片与媒体附件。
   - `.mote/settings.json`：笔记库级配置（优先于 `.obsidian/`）。
   - `.mote/workspace.json`：工作区状态（标签页、打开文件等）。

2. **保持文件树与库根目录极简清爽**：
   - 访达和命令行中，`.mote/` 属于隐藏目录，笔记库根目录仅展示 Markdown 笔记与分类文件夹。
   - mote 左侧文件树对用户自动隐藏 `.mote/`，编辑器中不会被大量散落的附件文件打扰。

3. **双链语法与透明寻址**：
   - 笔记内引用图片统一使用简洁的双链语法 `![[图片名.png]]`，不暴露内部 `.mote/attachments/` 路径细节。
   - 链接解析器与索引优先在用户可见目录查找，若无则自动在 `.mote/attachments/` 寻址。
   - `parseVaultPath` 放行受控的 `.mote/attachments/` 路径访问，确保 `mote-file://` 协议能够安全加载图片，同时严格防止路径穿越。

4. **向后兼容性**：
   - 兼容打开既有的旧笔记库；若库内尚无 `.mote/`，自动以现代默认配置运行，并在首次存入附件时按需建立 `.mote/attachments/`。

## 理由

- 笔记库重回纯粹本质：根目录下只有用户自己创作的笔记内容。
- 双链引用无相对路径依赖，后续移动或重命名笔记不会导致图片链接失效。
- 摆脱对第三方软件私有结构的依附，确立属于 mote 自己的技术标准与规范。
