# 0029 同步服务公开注册，用户用用户名和密码登录

- 状态：已接受，替代 0025 的登录部分
- 日期：2026-11-24

## 背景

[ADR 0025](0025-accounts-in-data-model-from-v1.md) 按账户建模，但只有一个账户，由命令行创建，没有登录。

2026-11-24 你决定：公开给用户注册。谁都可以在 mote 里建账户，用自己的笔记库。

这推翻了两条旧决定：

1. 0025 的"只有一个账户，由命令行创建"。
2. ADR 0022 的自签证书方案。公开用户没法手动固定证书。

## 决定

### 账户和登录

- 用户名加密码注册。用户名 3 到 32 个字符，大小写不敏感，存小写。
- 密码用 scrypt 加每个账户独立随机盐，只存哈希。
- 注册成功后返回一个恢复码，只显示一次。服务端只存它的哈希。
- 登录发设备令牌，就是原来那套令牌。密码只用于登录，不在客户端保存。
- 忘记密码用恢复码重设。重设后撤销这个账户的所有设备。
- 公开用户不靠命令行找回密码，也不需要邮箱。
- 登录和注册按 IP 限速。超限返回 429。

### 注册时自动准备的东西

- 一个账户，一个笔记库（名字 `vault`），一台设备（拿到令牌）。
- 默认每个账户 1 GiB 配额，所有笔记库共用。超了拒绝上传。
- 每账户最多 10 台设备。

### 证书和域名

- 公开服务要用公共机构签发的证书，这需要域名，在中国大陆还要备案。
- 备案完成前，先用自签证书给少数人用。
- 客户端把服务器地址和证书放进"高级"，主界面只有用户名和密码。

## 理由

- 用户只该记得用户名和密码。令牌、证书、地址是实现的细节。
- 恢复码不用邮件服务器就能找回密码，成本低。
- 配额和限速让一台小服务器也能承受陌生用户，那台机器只有 16G 磁盘和 933M 可用内存。
- 先做账户和登录，域名备案是外部等待，不阻塞代码。

## 后果

- 服务器会存别人的笔记。磁盘、内存、备份和法律责任都多一层。第一版不做备份，见 ADR 0027。
- 没有邮箱验证，用户名可以被抢注。以后要邮箱时再写 ADR。
- 恢复码丢了又忘了密码，账户就打不开了。管理员只有在具备服务器访问权时才能救。
- 公开注册后，登录接口会成为攻击目标。限速是第一道防线，密码哈希是第二道。
- 上线前必须有域名和可信证书。备案没完成就不能对公众开放。
