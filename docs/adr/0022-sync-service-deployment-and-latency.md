# 0022 同步服务部署在自己的阿里云服务器，按文件同步，延迟约 2 秒

- 状态：被 0027 替代（备份部分）
- 日期：2026-11-23

## 背景

ADR 0021 决定 mote 自己做同步服务，把数据结构、同步流程、合并规则和服务端部署留到第 10 步再定。本篇定下部署、实时性和合并规则。术语见 [CONTEXT.md](../../CONTEXT.md#同步)。实现计划见 [step-10.md](../plans/step-10.md)。

2026-11-23 查到的事实：

- 你有一台阿里云服务器，在杭州，公网 IP 固定。
- 你没有域名，也没有备案。
- 服务器内存 1.7G，可用 933M，没有 swap。根分区 40G，剩 16G。
- 服务器上跑着一套生产 ERP：4 个 Podman 容器（Postgres 16、`erp-server`、`erp-worker`、`erp-web`）。`erp-web` 占端口 80。主机上没装 Node。
- `~/life-os` 除 `.git` 外远小于 1G，超过 5M 的文件只有 1 个。

## 决定

### 部署

- 同步服务部署在这台阿里云服务器上，和 ERP 同一台。
- 同步服务是一个 Podman 容器，里面一个 Node 进程，用 TypeScript 写。它用 SQLite 存文件表，用磁盘目录按哈希存内容。数据放在主机目录 `/srv/mote-sync`。
- 同步服务不碰 ERP：不连它的 Postgres，不走它的 nginx，不用它的容器网络。
- 容器内存上限 300M。同步服务的存储上限 8G，到上限就拒绝上传，并先清理最旧的历史版本。
- 每天把 `/srv/mote-sync` 备份到杭州的阿里云 OSS。

### 连接

- 设备用公网 IP 和端口 8443 连同步服务，不用域名。
- 同步服务用自签 TLS 证书。设备做证书固定。
- 每台设备一个设备令牌。同步服务只有一个用户。
- 服务器地址、证书指纹和设备令牌是 mote 的设置，存在 `~/Library/Application Support/mote`。
- 第一版不做端到端加密。同步服务能读到笔记内容。

### 实时性

- 同步按单个文件进行，不做逐字实时。
- 目标：一台设备停止输入后约 2 秒，另一台开着 mote 的设备看到改动。
- 设备和同步服务之间保持一条 WebSocket。同步服务接受改动后立刻通知其他设备。
- 同步模块等一个文件 1.5 秒没有变化再上传。
- 笔记和附件分两个队列，笔记优先。
- mote 没开着时不同步，下次打开时补齐。

### 合并

- 设备上传时带上它基于的版本号。版本号不是这个文件的最新版本时，同步服务拒绝。设备拉取最新内容，合并，再上传。
- 两边都改过的笔记做三方合并。两边改了同一处时，两段都保留。
- 三方合并不能用时，生成冲突文件。不能用的情况：没有同步基准，或者文件不是合法的 UTF-8 文本。
- 附件不合并，后上传的赢。旧内容留作历史版本。
- 一边删除，一边修改：修改赢。
- 不同步 `.obsidian`、`.git` 和其他以 `.` 开头的目录。`.mote/attachments/` 例外，要同步。

## 理由

- **用自己的服务器，不用 Cloudflare。** 服务器已经付了钱。一个进程加一个 SQLite 文件，比拼四个云服务简单。同一个进程能在 Mac 上跑，测试用它。
- **用 IP 加证书固定，不买域名。** 服务器在中国大陆，域名要备案才能用，要等一到三周（估计）。用 IP 访问不受备案限制。自签证书的加密强度和普通证书一样，证书固定补上"证明对方是谁"这一步。
- **用容器。** 主机上没装 Node，现有服务都跑在 Podman 里。容器让同步服务和 ERP 互不影响，内存上限也靠它实现。
- **设两个上限。** 同步服务和生产 Postgres 共用内存和磁盘。磁盘写满或内存用满都会让 ERP 停。服务器没有 swap，内存用满时系统直接杀进程。
- **按文件同步。** 你一个人用，很少两台设备同时改同一篇笔记。逐字实时要把编辑器和服务端换成 CRDT 这类数据结构。Obsidian Sync 也是按文件同步。
- **等 1.5 秒再上传。** mote 连续输入时最多 800 ms 保存一次。每次保存都上传，会每 800 ms 产生一个历史版本。
- **保留冲突文件。** Obsidian 官方说自动合并"有时会产生重复文字或格式问题"，它从 1.9.7 起提供冲突文件这个选项。
- **不做端到端加密。** 加密后同步服务读不到笔记内容，以后的 AI 和语音处理就不能放在同步服务上。

## 后果

- 同步服务在生产服务器上多开一个公网端口。它靠 TLS、证书固定和设备令牌保护。你在 2026-11-23 接受了这个风险。
- 要在阿里云安全组里放行 8443 端口的入方向。
- 换服务器或换 IP 时，每台设备都要改设置。以后改用域名也只改设置。
- 服务器磁盘坏了会丢历史版本。每台设备的本机笔记库是完整副本，笔记不会丢。OSS 备份用来恢复历史版本。
- 同步服务能读到笔记内容。服务器被攻破，笔记就泄露。
- iOS 版在后台时不能保持长连接，切回前台才同步。
