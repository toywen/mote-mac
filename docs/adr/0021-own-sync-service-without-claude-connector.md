# 0021 同步用 mote 自己的服务，不考虑 Claude 连接器

- 状态：已接受，替代 0005
- 日期：2026-11-23

## 背景

ADR 0005 决定 mote 自己做同步服务。它把"Claude 连接器能写入"当作选方案的一个条件，还让 Claude 连接器在 iOS 版做出来之前负责手机上的记录。

2026-11-23 决定不做 Claude 连接器，选方案时也不考虑它。同步服务的客户端只剩 Mac 端和以后的 iOS 版。

去掉这个条件后，候选方案重新比较：

| 方案                      | 费用                               | iOS 端                    | 冲突处理                        | 问题                                                         |
| ------------------------- | ---------------------------------- | ------------------------- | ------------------------------- | ------------------------------------------------------------ |
| git + GitHub              | 免费                               | 弱                        | 同步停下，要手动解决            | 不方便                                                       |
| iCloud Drive              | 免费                               | 好，Obsidian iOS 直接可用 | 生成"笔记 2.md"这样的重复文件   | Electron 用不了 Apple 的文件协调接口，同时写入有风险（推断） |
| Self-hosted LiveSync 协议 | 自建 CouchDB                       | Obsidian iOS 插件可用     | 自动合并                        | 数据格式绑定这个插件，兼容成本高                             |
| mote 自己的同步服务       | 云服务免费额度内，可能为 0（猜测） | 自己的 iOS 版接入         | 自动合并，和 Obsidian Sync 一样 | 要写服务端                                                   |

## 决定

- mote 自己做同步服务，按单个文件同步，两边都改过的笔记自动合并。和 Obsidian Sync 的做法一样。
- git 不再用于同步。
- 同步服务的客户端是 Mac 端和以后的 iOS 版。不做 Claude 连接器。
- 同步不进第一版，放在开发顺序第 10 步。数据结构、同步流程、合并规则和服务端部署到时再定。

理由：它是唯一同时满足两件事的方案。两边都改过的笔记自动合并，数据格式不绑定别人的插件。以后的 AI 和语音处理也能放在同一个服务上。

iCloud Drive 不再因为 Claude 连接器被排除。排除它的理由只剩两条：冲突时生成重复文件，Electron 同时写入有风险。第二条是推断，还没验证。

## 后果

- 开发和试用期间，`~/life-os` 继续用 obsidian-git 备份。试用时让 Obsidian 在后台开着。mote 同步上线后再关掉 obsidian-git。
- iOS 版做出来之前，手机上没有客户端可用，也没有替代的记录办法。
