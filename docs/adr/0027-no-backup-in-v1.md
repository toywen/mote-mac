# 0027 同步第一版不做自动备份

- 状态：已接受，替代 0022 的备份部分
- 日期：2026-11-23

## 背景

[ADR 0022](0022-sync-service-deployment-and-latency.md) 决定每天把 `/srv/mote-sync` 备份到杭州的阿里云 OSS。[ADR 0026](0026-sync-storage-layout.md) 原先把 OSS 写成"只做备份"的角色。

2026-11-23 你决定第一版不做备份，也不接 OSS。

## 决定

- 第一版不做自动备份。数据只在服务器的 `/srv/mote-sync` 上。
- 不接 OSS。
- 每台设备的本机笔记库是完整副本。服务器磁盘坏了，笔记本身不会丢。
- 换成第二台服务器或迁移时，手动拷贝 `/srv/mote-sync`。拷贝前先停容器。
- 8G 存储上限保留，防止写满磁盘拖垮 ERP。
- 以后要做备份时，先写一篇新 ADR，倾向的做法是加密快照传到 OSS。

## 理由

- 数据小：当前约 8M，估计稳定在 100 到 200M。
- 服务器短时间内坏了，损失是历史版本和合并用的基准内容。笔记正文在每台设备上都有。
- 备份本身就是一套功能：定时、加密、密钥保管、恢复演练。第一版先省掉。
- ERP 是生产系统，少接一个外部服务，少一处出错的地方。

## 后果

- 服务器磁盘坏了，历史版本全丢。
- 想回滚一篇笔记到旧版本，要靠各设备本地的副本。
- 换服务器要手动拷贝目录，不能从云端拉回来。
- 没有备份，也就没有备份泄露的风险。
