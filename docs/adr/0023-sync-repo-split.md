# 0023 同步服务和协议独立成 mote-sync 仓库

- 状态：已接受
- 日期：2026-11-23

## 背景

[ADR 0022](0022-sync-service-deployment-and-latency.md) 定下了同步服务的部署、实时性和合并规则，但没有说代码放在哪。候选方案：

| 方案                        | 好处                                     | 代价                                |
| --------------------------- | ---------------------------------------- | ----------------------------------- |
| 同一仓库的 `server/` 目录   | 一次提交改两边，合并规则只有一份         | 两边的构建、发布和版本绑在一起      |
| 独立仓库，协议发布成 npm 包 | 生命周期和发布分开，协议说明有独立的位置 | 改协议要动两个仓库，本地调试要 link |
| 独立仓库，协议各复制一份    | 最省事                                   | 两份合并规则会慢慢不一致，出错难查  |

## 决定

- 新建仓库 `mote-sync`。协议包和同步服务都在它里面。
- 协议包 `@mote/sync-protocol` 是纯 TypeScript，没有依赖。它包含协议类型、合并规则和 `protocol/README.md` 里的协议说明。
- 协议包在打标签时由 CI 发布到 npm 公开源。
- `mote-mac` 依赖 `@mote/sync-protocol`。合并规则和协议类型在 `mote-mac` 里只有这一份，不复制。
- 改协议时先做加法：服务端先接受旧客户端的请求，客户端升级后再删旧字段。删字段要先停用一个版本。
- iOS 版按 `protocol/README.md` 用 Swift 实现。协议说明的改动和协议类型在同一个提交里。

## 理由

- 同步服务比 Mac 应用活得长。它是 iOS 版唯一的后端，Mac 应用换实现它也照常运行。
- 两边发布节奏不同：Mac 应用跟着 GitHub Releases 走，同步服务跟着容器镜像走。
- iOS 用 Swift，协议包对它没用。协议说明必须有独立的家，否则写在 Electron 仓库里，做 iOS 时找不到。
- 现在的客户端还没发布，改协议不会破坏谁。等到两边都在用，加法式升级就是必须的。

## 后果

- 改协议要两个提交：先发协议包的版本，再在 `mote-mac` 里升级依赖。
- 本地同时改两个仓库时用 `npm link`，或者在 `mote-mac` 里临时指向本地路径，提交前改回来。
- npm 的 `@mote` 已被占用的话，包名改成 `mote-sync-protocol`，决定不影响结构。
- `mote-mac` 的 CI 要从 npm 安装协议包。包是公开的，不需要令牌。
