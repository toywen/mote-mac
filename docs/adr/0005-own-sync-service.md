# 0005 同步用 mote 自己的服务，不用 git

- 状态：已接受
- 日期：2026-11-20

## 背景

`~/life-os` 现在靠 Obsidian 的 obsidian-git 插件每分钟 commit 并 push。这个插件只在 Obsidian 开着时运行。以后还要有 iOS 端和能写入笔记的 Claude 连接器。

候选方案：

| 方案                      | 费用                               | iOS 端                    | Claude 连接器能写入吗       | 冲突处理                        | 问题                                                         |
| ------------------------- | ---------------------------------- | ------------------------- | --------------------------- | ------------------------------- | ------------------------------------------------------------ |
| git + GitHub              | 免费                               | 弱                        | 能                          | 同步停下，要手动解决            | 不方便                                                       |
| iCloud Drive              | 免费                               | 好，Obsidian iOS 直接可用 | 不能，云端服务写不进 iCloud | 生成"笔记 2.md"这样的重复文件   | Electron 用不了 Apple 的文件协调接口，同时写入有风险（推断） |
| Self-hosted LiveSync 协议 | 自建 CouchDB                       | Obsidian iOS 插件可用     | 要实现它的协议              | 自动合并                        | 数据格式绑定这个插件，兼容成本高                             |
| mote 自己的同步服务       | 云服务免费额度内，可能为 0（猜测） | 自己的 iOS 版接入         | 能，和客户端走同一个接口    | 自动合并，和 Obsidian Sync 一样 | 要写服务端                                                   |

## 决定

- mote 自己做同步服务，按单个文件同步，两边都改过的笔记自动合并。和 Obsidian Sync 的做法一样。
- git 不再用于同步。
- 同步不进第一版，放在开发顺序第 8 步（原规划第 7 步，增加打包步骤后顺延）。数据结构、同步流程、合并规则和服务端部署到时再定。

理由：它是唯一同时满足三件事的方案。iOS 端是你自己的 app，Claude 连接器能写入，以后的 AI 和语音处理也能放在同一个服务上。

## 后果

- 开发和试用期间，`~/life-os` 继续用 obsidian-git 备份。试用时让 Obsidian 在后台开着。mote 同步上线后再关掉 obsidian-git。
- Claude 连接器是同步服务的另一个客户端。它只新建文件，所以不会和已有笔记冲突。
- iOS 版做出来之前，手机上没有客户端可用。这段时间手机上记录靠 Claude 连接器。
